# dsh-context-bridge

DSH 会话**手动**交接。当你判断一个会话的上下文确实用不下去了，点一下菜单里那一行：插件把「当前目标 / 已做到哪 / 下一步 / 项目事实」压成一份交接文档，新建一个会话并把这份文档作为它的第一轮投入、把它唤醒接着干。新会话还能继承源会话在会话总线上的注册名。

**它不是自动的**。没有阈值、没有定时器、没有监听 agent 循环。这是有意的：上下文快满时第一件事应该是压缩，只有压缩几轮之后确实压不动了，交接才是最后一步 —— 这个判断只有人能做，一个数字猜不出来。

默认**关闭**。在项目根建 `.dsh-bridge.json` 才生效。

---

## 唯一触发点

只有一处：会话行 `…` 菜单里的 **上下文交接：生成并续接**（或侧栏面板里的 **立即交接**）。插件里没有第二个地方能启动交接。

## 产出长什么样

一份四节的 Markdown，刻意写短 —— 把整段对话复述一遍的交接文档，自己又会撞上同一堵墙：

| 小节 | 内容 |
|---|---|
| 现在要做什么 | 进行中的待办，没有就取最后一轮的要求与结论 |
| 已经做到哪 | 已完成的待办 + 最近一次压缩摘要（裁剪后） |
| 下一步 | 剩余待办，按顺序 |
| 项目事实 | 工作目录 + 最近几轮（要求 → 结果） |

全部从源会话自己的事件日志生成（`sessionQuery.observeSession`，只读），**不调模型**：不花 token，也不会编造没给它的东西。

## 新会话是怎么起的

1. 把交接文本做成一条普通的 `user/message`（宿主只要求 id 非空、`role: "user"`、`source.kind` 非空、`content` 是数组）；
2. `agents.create({ sessionId, seed, inheritedEventCount, meta })` 建会话，这条事件就是它的第一条事件，由宿主自己持久化；
3. 再把同一份文本通过 `agent.followup()` 投进去，**让它真的开始干活**，而不是挂着一份文档不动。

宿主没有 `agents.create` 时，明确报原因，不建任何东西。

## 继承会话总线的注册名

源会话在会话总线名册（`.dsh-bus/names.json`）里有名字时，新会话登记为 `<名字>-handoff`（被占就 `-handoff-2`、`-3`……）。本插件对名册**只读**，写入走会话总线自己的登记入口（总线在场且暴露了才写）；任何已有名字都不会被覆盖，名字最长 64 字符。

## 怎么开

```json
// <项目>/.dsh-bridge.json
{
  "enabled": true,
  "todoLimit": 12,
  "recentTurns": 3,
  "openNewSession": true
}
```

| 键 | 默认 | 含义 |
|---|---|---|
| `enabled` | `false` | 文件不存在或为 `false` = 菜单行拒绝执行，并告诉你怎么开 |
| `todoLimit` | `12` | 文档里最多列几条待办 |
| `recentTurns` | `3` | 总结最近几轮 |
| `openNewSession` | `true` | 交接后把界面切到新会话 |

打开开关**不会**让任何东西自己跑起来 —— 它只决定你那一击准不准执行。

## 界面

- 会话行 `…` 菜单里的一行，加侧栏一个面板图标；
- 都走官方 slot 注册。Client 半**没有 DOM 变更观察器、不手动操纵宿主容器、不测量布局、不跑定时器** —— 由 `tests/client-safety.test.mjs` 静态扫描把关，任何一条重新出现，测试就失败。（姊妹插件 dsh-session-send 的菜单兜底曾造成「插入 → 重渲染」自激，打开模型菜单时锁死渲染主线程；本插件的结构让那个 bug 无法在这里复现。）

## 已知边界

- 只覆盖**会话日志里存在的事实**。只在人脑子里、没落盘的东西不在里面。
- `agents.create` 是宿主 API；不提供的宿主上，插件会说明原因，不会假装成功。
- 新会话继承的是 cwd 和 `parentSession` 指向，不是完整父历史。
